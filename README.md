# 边缘 AI 智能手环（STM32F103）

基于 STM32F103C8T6 的智能穿戴实训项目。所有数据在终端本地采集、运算、判断并直接执行控制，不依赖手机或云端。

## 功能

| 功能 | 实现 |
|---|---|
| 心率检测 | MAX30102 红外 PPG + 峰值检测算法，静止状态误差约 ±3 bpm |
| 血氧（参考值） | MAX30102 双波长 PPG，500 点窗口 + R 值经验公式，每秒刷新，典型精度 ±5% |
| 体温 | DS18B20 单总线，0.1℃ 分辨率 |
| 环境温湿度 | DHT11 |
| 六轴姿态 | MPU6050（加速度 + 陀螺仪，硬件 I2C1） |
| 计步 | MPU6050 合加速度 + 阈值/死区峰值检测，含步频与静止判定 |
| 显示 | 1.3 寸 OLED（SSD1306），五页界面，KEY1 翻页 |
| 蓝牙通信 | HC-05/HC-06，手机 App 收发命令、上报数据 |
| 异常报警 | 心率越界或血氧 <90% 连续约 10 秒 → 蜂鸣器 + 双 LED 闪烁 + 屏幕提示 |

## 硬件

- 主控：STM32F103C8T6 核心板（64KB Flash / 20KB RAM）
- 板卡：STM32 课程开发板（手环 / 智能插座 / 环境检测三合一）
- 无线：HC-05 蓝牙模块（UART 透传）

## 实现要点

**MAX30102 数据读取**

硬件 FIFO 只有 32 格，关闭硬件平均后是 100Hz 原始采样，0.32 秒就写满。主循环每 10ms 调用 `MAX30102_Poll()`，按硬件读写指针差值把积压样本搬进 128 组软件环形缓冲，保证读到的永远是新鲜数据。

同一组样本喂给两个消费者，绝不重复读 FIFO（读指针是单向的，读两次就丢一组）：

```
FIFO(32) → Poll → 软件环形缓冲(128) → Pop ─┬→ HR_Feed100Hz(ir)   内部 4 点平均抽取到 25Hz
                                          └→ SPO2_Feed(red, ir)  100Hz 双通道，500 点滑窗
```

**心率算法**（`APP/max30102/hr.c`）

```
IR 原始值
  → 一阶低通跟踪直流分量（τ ≈ 1.3s）
  → 相减得到带符号交流分量（不取绝对值，否则每拍出两个峰）
  → 局部极大值检测（高于前后点，且超过峰值一半）
  → 两个峰的间隔 IBI，必须落在 12~50 样本（30~125 bpm）
  → 4 点滑动平均输出心率
```

手指贴上瞬间直流分量从千级爬到十万级，这段过渡期的交流值会异常大，因此加了「直流收敛判断」：连续稳定约 2.4 秒后才开始峰值检测。

**血氧算法**（`APP/max30102/spo2.c`）

完全按实验指导书第九节实现，全部整数运算：

```
500 点双通道窗口（5 秒 @100Hz，每秒滑窗补 100 点）
  → 心率支路（只用于输出 HR2 做交叉校验）：
       去直流 → 4 点滑动平均 → 差分 → 5 点 Hamming 卷积[41,276,512,276,41]/1146
       → 自适应阈值（|卷积|均值 ×1.3）峰值检测，最小峰距 8 点 → HR = 6000×(n-1)/总间隔
  → 血氧支路（与峰检测完全解耦）：
       DC = 整窗均值
       AC = 整窗 RMS（先做 4 点平均抑制工频，再剔除偏离 DC>2% 的离群点）
       → R = (ACred/DCred) / (ACir/DCir)，3 次滑动平均后乘经验增益 0.40
       → SpO2 = -45.060R² + 30.354R + 94.845（定点实现，等价 184 项查表）
```

实现要点：

- **必须 100Hz**：官方算法的 500 点、最小峰距 8、`6000/T` 全按 100Hz 设计，所以 `FIFO_CONFIG` 从 `0x5F`（4 次平均）改成 **`0x1F`**（不平均 + 保留回绕）。心率算法仍跑 25Hz，由 `HR_Feed100Hz()` 在软件里补回 4 点平均，参数一行未改。
- **回绕位不能丢**：部分资料给出的 `0x0F` 会把 bit4 的 ROLLOVER 清零，100Hz 下 FIFO 0.32 秒就写满并停止采集，表现为心率、血氧永久无数据。
- **血氧不依赖峰检测**：弱信号下 5 秒窗口内的峰数实测在 0~12 之间跳，一旦不足 3 个峰，按"逐搏动统计"的写法整次计算就作废。改为整窗峰峰值后，血氧与心率彻底解耦，`valid` 不再随峰数抖动。
- **AC 必须先平滑**：心率支路一直有 4 点平均，血氧支路最初漏了，直接拿 100Hz 原始值算 max-min，50/100Hz 工频被当成 AC，实测红光 AC 比红外大 87%、R 被抬到 2.2。
- **AC 用 RMS 而不是峰峰值**：`max-min` 会被单个残留尖峰决定，实测 R 在 0.36~0.79 之间跨 2.2 倍；换成均方根后单个尖峰的影响被 500 个样本摊薄，R 与 SpO2 才稳得住。RMS 与峰峰值的换算系数在 R 的分子分母上会约掉，中心值不变，只减小方差。
- **LED 电流自动增益**：反射式 PPG 对压力极敏感，压太紧时表面反射增强、毛细血管压闭，DC 冲高到接近满量程（262143）而 AC 几乎消失。`MAX30102_AgcStep()` 每 2 秒按实测 DC 把电流拉回量程中段（目标 13.5 万），步进按比例一次到位；调整后 `SPO2_Reset()` 重新积累窗口。
- **全定点**：R 值用 x1000 表示；先算 `AC×1e5/DC` 的千级比例再相除，避免 32 位溢出；SpO2 用展开后的定点二次式，不引入浮点库。
- **无效就显示 `--`**：直流 <5 万（手指不在位）、峰数 <3、心率超 30~200、R 超出 0.30~1.80、SpO2 超 70~100，任一不满足都判本次无效，**不保留上一次数字**。
- **运动门控**：`STEP_IsMoving()` 为真时血氧结果一律不采信，P5 页显示 `MOVE! PAUSED`。
- **资源占用**：4 个 500 点数组 = 8KB RAM（总占用 11.2KB / 20KB），一次计算约 0.7ms（每秒一次）。

**计步算法**（`APP/step/step.c`）

```
MPU6050 三轴加速度（mg）
  → mag = sqrt(ax² + ay² + az²)          与佩戴方向无关，只看运动冲击
  → 5 点滑动平均（50Hz，即 100ms 窗）      滤掉手抖/路面颠簸的高频毛刺
  → 上升沿穿越阈值 TH = 1200mg            与静止基线 1000mg 拉开的距离即灵敏度
  → 回落到 1050mg 以下才重新武装           施密特迟滞，防止在阈值附近抖动重复计数
  → 与上一次峰值间隔 ≥ 300ms              死区时间，同一步的二次抖动被丢弃
  → 两个条件同时满足，步数 +1
```

参数取值：采样率 50Hz（20ms）保证每个步态周期有 15~25 个样本；窗口 100ms 对 1~2Hz 的步态波峰只衰减约 6%；300ms 死区对应人体极限步频 200 步/分钟，正常步行 90~130、跑步 160~180 都落在死区之外。步频由最近 4 次步间隔平均后换算（60000 / 平均间隔），3 秒无新步判定为静止、步频输出 0。

边界处理：合加速度超出 300~6000mg（I2C 全 0、自由落体、剧烈撞击）的样本直接丢弃并计入错误计数；连续 25 个异常样本（0.5s）判定传感器故障，复位检测器并在计步页（P3）显示 `I2C ERR`，恢复后自动重新计步，已计步数不丢。采样时间基准用 TIM2 自由计数器（10kHz，增量累加），不靠主循环次数估算，也不开定时器中断，因此 OLED 刷屏、DHT11/DS18B20 位操作造成的循环抖动不会影响 300ms 死区。

**报警逻辑**

心率低于 50 或高于 110，连续 5 次采样周期（约 10 秒）才确认，避免单次测量抖动误报。报警时蜂鸣器与 LED 间歇闪烁，优先级高于手动开关状态；心率恢复后自动解除。

低血氧报警独立判定：SpO2 < 88% 且结果有效（算法判有效 + 手指在位 + 未运动），连续约 30 秒确认。阈值和确认时间都比心率报警宽松，原因是血氧数值未做标定、抖动更大，宁可漏报也不要误报。心率与血氧共用一套闪烁节拍，避免两个报警抢蜂鸣器；蓝牙 `DATA` 用 `ALARM` / `LOWO2` 后缀区分。

## 已知限制

- **血氧含经验校准系数**：实测校准前 R 停在 1.7~2.1，比生理预期（0.5~0.7）高出 3 倍左右，直接代入公式只有 70~80%。`spo2.h` 里用 `SPO2_R_GAIN 2/5`（即 ×0.40）把它拉回 94~97%。**这个系数是按"正常人血氧 95~99%"反推的，不是用商用血氧仪标定的结果**，且依赖"两路 LED 电流相同、DC 基本相等"的前提——换模块、换结构、改电流策略都要重新确定。数值只能看趋势，不能作为诊断依据。
- **两路 DC 必须配平**：R 的公式是 `(ACred/DCred)/(ACir/DCir)`，两路 DC 一旦失衡，比值会直接放大 R（实测红光电流取红外的 85% 时，DC 比掉到 0.82，等于把 R 乘了 1.21，SpO2 凭空少 10 个百分点）。
- **血氧对压力极敏感**：手指压太紧时表面反射增强、毛细血管压闭，AC 几乎消失，表现为"贴着测不到、松开一点才有数"。软件用 AGC 把 DC 拉回量程中段，但根本解法是结构上加弹性压紧件与遮光罩。
- **板载结构无遮光件**：环境光（尤其 660nm 附近能量很强的暖光灯）会直接进红光通道，强光下读数会跳。
- **血氧刷新慢**：受 5 秒窗口限制，结果每秒才更新一次，不能反映瞬时变化；运动过程中直接暂停采信。
- **蓝牙 AT 模式不可用**：板上模块 EN 脚悬空，无法通过 GPIO 拉高进入 AT 模式，只能使用出厂默认名称与波特率。
- **OLED 为软件 I2C**：刷屏约 40ms，若后续增加刷新频率需改硬件 I2C 或 DMA。
